About this project

Relay is a small dispatch product I built to learn DevOps by typing every file. Same application from Docker Compose, to Kubernetes on kind, to Amazon EKS. The product does not change. The environment around it does.

browser web API Redis relay:jobs worker

Compose — five containers, one command

The first real run. One file starts the whole product on the laptop.

One Compose file starts all five containers. Only web publishes 8080:80. The others find each other by service name, not by localhost.

GitOps on kind — Argo watches git

Git is the source of truth. Argo syncs the Helm chart. CI does not kubectl apply.

Argo watches charts/relay and syncs namespace relay. Argo does not load images. You still kind load first.

Terraform lab — state on S3, not EKS yet

Infrastructure as code before the production-shaped cluster.

Terraform creates the lab from files. State lives on S3. DynamoDB locks the apply. The extra empty bucket is not Relay. This is not EKS.

Observability — scrape inside the cluster

Kubernetes Ready is not enough. Prometheus checks the API is actually up.

Prometheus scrapes the API Service inside the cluster. Grafana only graphs what Prometheus stored. /metrics is not on Ingress.

Relay on Amazon EKS

Same chart. Private nodes. Public NLB. No bastion.

Relay on EKS reuses the lab VPC. Public subnets hold NAT and the NLB. Private subnets hold the worker nodes. GitHub Actions pushes images to ECR with OIDC. Users hit NLB → ingress-nginx → web. Prometheus and Grafana stay off the public URL.
